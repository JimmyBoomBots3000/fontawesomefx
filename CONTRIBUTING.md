# Contributing to FontAwesomeFX

Bug reports, documentation improvements, tests, and focused pull requests are
welcome. This repository is an independent fork of FontAwesomeFX by
[Jens Deters](https://github.com/Jerady).

## Report a bug or propose a feature

Search the [issues](https://github.com/JimmyBoomBots3000/fontawesomefx/issues)
before opening a new one. For a bug, include:

- The FontAwesomeFX version or commit, JDK and JavaFX versions, and operating system.
- Steps to reproduce, expected behavior, and actual behavior.
- A small runnable example, relevant logs, and screenshots when they help.
- For icon problems, the enum constant, font style, size, and any applied CSS.

Discuss substantial features, public API changes, dependency additions, or new
icon packs in an issue before implementing them. This helps establish the scope
and compatibility requirements before you spend time on the change.

## Set up and build

Fork the repository, create a branch for your change, and use **JDK 17 or newer**.
The Maven Wrapper supplies Maven. On Windows, use `mvnw.cmd` in place of `./mvnw`.
If macOS is selecting an older JDK:

```sh
export JAVA_HOME=$(/usr/libexec/java_home -v 17)
```

From the repository root, build and run the regular tests:

```sh
./mvnw clean verify
```

For changes affecting public API documentation:

```sh
./mvnw -Pjavadoc verify
```

For icon rendering, sizing, CSS, or viewer changes, also run the desktop tests
on a machine with a graphical display:

```sh
./mvnw -pl :fontawesomefx-fontawesome -am -Dfontawesomefx.uiTests=true test
```

To inspect the viewer manually, first install its modules locally:

```sh
./mvnw -pl :fontawesomefx-fontawesome -am install
./mvnw -pl :fontawesomefx-fontawesome javafx:run
```

## Implementation guidelines

Keep changes focused and follow the surrounding code style, using spaces rather
than tabs. The libraries compile with `--release 11`: production code must use
Java 11-compatible syntax and APIs even when your build JDK is newer.

Preserve existing public APIs, Java module descriptors, historical icon names,
and copyright and attribution notices. New independent functionality belongs in
`io.github.jimmyboombots3000.fontawesomefx`; inherited library APIs retain their
existing packages for compatibility.

Add regression tests for behavioral fixes. For font rendering issues, exercise
the view in a scene and apply CSS: checking the font before CSS has run can miss
fallback-font bugs. Test solid, regular, and brand styles when the change affects
font selection. Include screenshots for visible UI changes when practical.

Font Awesome's enum catalog is generated by Groovy during Maven's
`generate-sources` phase. Change `scripts/generate-fontawesome.groovy` or the
module's `src/main/fontawesome/` metadata, compatibility mappings, or template;
then build normally. Do not edit or commit Java under `target/generated-sources`.
For an upstream font update, use the explicit import profile described in the
[README](readme.md#icon-names-and-compatibility). Keep bundled font files, mappings,
metadata, and license notices consistent. Normal builds must not modify tracked
source inputs. Leave project version changes to the maintainer.

## Submit a pull request

Open a pull request from your branch against this repository's default branch.
Explain the problem and resulting behavior, link any related issue, and list the
commands you ran with their results. Note public API or dependency changes and
any limitations you could not test.

Keep unrelated changes in separate pull requests. Respond to review feedback
and update your tests as needed. Changes to build, automation, and contribution
or licensing policy are assigned to the repository owner for review.

license, and relevant notices in the pull request so compatibility can be reviewed.

Bundled fonts and artwork keep their own licenses; they are not automatically
relicensed under Apache 2.0. Preserve the notices in
[THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md) and [licenses/](licenses/), and
